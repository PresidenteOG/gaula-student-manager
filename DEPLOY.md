# Deploying GAULA

**Live API:** https://gaula-student-manager.onrender.com — Render free tier, deployed from `render.yaml`.
**Live web client:** https://presidenteog.github.io/gaula-student-manager/ — Flutter web build on GitHub Pages (see below).

The backend has a `demo` profile that runs the whole API with **no external services**: an
in-memory H2 database that Hibernate builds from the entities, filled on every start by
`DemoDataSeeder` with a small fictional school (four teachers, two DAM groups, nine students, a
weekly schedule). Every account's password is `admin123`.

## Backend — Render (matches `render.yaml`)

### What's in the repo for this

- **`Dockerfile`** — two-stage build (Maven → JRE 21) from `Backend/`.
  `docker build -t gaula . && docker run -p 8080:8080 -e GAULA_JWT_SECRET=anything gaula` works as-is.
- **`render.yaml`** — a Render blueprint: one free Docker web service, `SPRING_PROFILES_ACTIVE=demo`,
  `GAULA_JWT_SECRET` generated by Render, health check on `/v3/api-docs`.
- **`Backend/src/main/resources/application-demo.properties`** — the demo profile: H2, Flyway off,
  `ddl-auto=create-drop`, `server.port=${PORT:8080}`, CORS open to any http/https origin.

### Steps

1. Sign in at <https://render.com> with the GitHub account.
2. **New → Blueprint**, pick `PresidenteOG/gaula-student-manager`. Render reads `render.yaml`.
3. **Apply**. First build is ~4–6 min (Maven downloads the Spring dependency tree once).
4. The URL is `https://gaula-student-manager-XXXX.onrender.com`.
   Check `GET /v3/api-docs` returns 200, then `POST /api/auth/login` with
   `{"username":"admin","password":"admin123"}`.
5. Put the URL in this file's header, the root README, and the profile README row.
6. Optional: add `CORS_ALLOWED_ORIGINS` in the dashboard once the web client is live, set to its
   origin (e.g. `https://presidenteog.github.io`), to stop allowing every origin.

Free instances sleep after ~15 min idle; the next hit takes ~30 s to wake, and every deploy or
sleep wipes the in-memory data back to the seed. Fine for a portfolio link — say so next to it.

## Web client — Flutter web on GitHub Pages

The Flutter app in `Frontend/` builds to static files and talks to the API over HTTP.

1. Point it at the deployed API. `Frontend/env/prod.json`:
   ```json
   {
     "APP_ENV": "prod",
     "API_BASE_URL": "https://gaula-student-manager-XXXX.onrender.com/api/",
     "UPLOADS_BASE_URL": "https://gaula-student-manager-XXXX.onrender.com/uploads/profiles/",
     "CONNECT_TIMEOUT_S": "20",
     "RECEIVE_TIMEOUT_S": "40",
     "SEND_TIMEOUT_S": "20"
   }
   ```
2. Build:
   ```
   cd Frontend
   flutter build web --release \
     --dart-define-from-file=env/prod.json \
     --base-href=/gaula-student-manager/
   ```
3. Publish `Frontend/build/web`. Either push it to a `gh-pages` branch, or use the
   `.github/workflows/deploy-web.yml` workflow (build on push to `master`, deploy to Pages).
4. The client URL is `https://presidenteog.github.io/gaula-student-manager/`.
   Log in with `admin` / `admin123`.

Cold starts: the first request after the API has slept takes ~30 s. The login screen should
surface that as a timeout-and-retry rather than a hard error.

## What a visitor can and can't do

Safe to leave open. The only accounts are the seeded ones (`admin`, `ifernandez`, `jpuig`,
`msoler`, and nine students), all `admin123`. There is no sign-up. The in-memory database is
rebuilt from the seeder on every start and every free-tier sleep, so nothing a visitor creates,
edits or deletes survives. Profile-photo uploads go to an ephemeral temp dir. The only outbound
call is to the public holiday API (`date.nager.at`) for the calendar; password-reset "emails"
are written to the server log, not sent.

## Local run

```
cd Backend
GAULA_JWT_SECRET=local-dev-secret ./mvnw spring-boot:run -Dspring-boot.run.profiles=demo
```

Then `http://localhost:8080/swagger-ui.html` for the API, or run the Flutter app against
`env/dev.json`.
